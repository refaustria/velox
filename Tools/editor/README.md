# Tools/editor

Editor Python scripts, run headless with the `pythonscript` commandlet (PythonScriptPlugin is enabled for Editor targets in `Velox.uproject`).

- `create_bootstrap_content.py` - creates `L_Empty`, Enhanced Input assets and the default data assets. Idempotent. See `docs/content-bootstrap.md`.
- `create_movement_test_map.py` - builds `/Game/Maps/L_MovementTest` (ADR 0002 section 7) plus flat unlit `/Game/Materials/M_Greybox_*` materials. Idempotent (deletes and rebuilds the map), asserts actor counts and raises on mismatch. Layout: 5120 cm strafe corridor with markers every 512 cm (text in Q3 units and metres), ramps 10/20/30/45/50 deg, stairs with 20/40/60 cm risers, 3 jump-pad placeholders with target markers (replace by `AVeloxJumpPad` in task 04), 3 bunny-hop gaps (500/700/900 cm over a 100 cm pit; each with a walled floor-height runway behind its 800 cm start platform, 1200/2500/4500 cm long, markers every 512 cm, a PlayerStart at the runway start, and 4 x 20 cm exit steps from the pit back onto the start platform), 5 PlayerStarts (corridor, pads, 3 gap runways), static sun and sky light. Materials are flat colours (no checker); geometry is `/Engine/BasicShapes` cubes and cylinders. Run:
  `UnrealEditor-Cmd Velox.uproject -run=pythonscript -script=Tools/editor/create_movement_test_map.py -nullrhi -unattended -nopause -nosplash -stdout -FullStdOutLogOutput`
  (first run compiles engine shaders on the CPU, allow ~10 minutes).

Notes on the 5.8 Python API (learned the hard way):
- `UPROPERTY(EditDefaultsOnly)` members of *structs* cannot be set with `set_editor_property`; pass them to the struct constructor kwargs instead (`unreal.VeloxInputAction(input_action=..., input_tag=...)`).
- `unreal.GameplayTag` has no constructor args; use `t = unreal.GameplayTag(); t.import_text('(TagName="InputTag.Move")')`.
- `unreal.Key` likewise: `k = unreal.Key(); k.set_editor_property("key_name", "SpaceBar")`.
- `InputMappingContext.map_key()` returns the mapping by value; attach modifiers by editing `default_key_mappings.mappings` and writing the struct back.

Map findings from the task-05 scripted runs (all fixed in `create_movement_test_map.py`; map regenerated):
- `unreal.Rotator` takes `(roll, pitch, yaw)`: ramps now use `Rotator(0, deg, 0)` (pitch; verified with `velox.move.Probe`, height rises along +X and is constant along Y) and text actors `Rotator(0, 0, 180)`.
- Marker/target meshes (`collide=False`) now also get `set_collision_profile_name("NoCollision")`; `set_collision_enabled` alone left a blocking profile at runtime.
- Corridor `PlayerStart` moved to (120, 0, 100) (was overlapping the back wall).
- Pad C target raised 40 cm (capsule centre z 750, marker disc at z 680) so the apex clears the ledge top (640); `PadRun.json` pad C leg holds forward for 1.0 s after the launch, then coasts onto the ledge.

Movement scripts and tooling: see `docs/movement-tooling.md`.

- `create_combat_test_map.py` - builds `/Game/Maps/L_CombatTest` (ADR 0003 section 6): 4000 x 4000 cm arena, 400 cm perimeter walls, 8 cover blocks, 4 PlayerStarts near the corners (first one at (-1700,-1200) faces +X), 3 `AVeloxDummySpawner` (`bAutoSpawn`) at 1000/2000/3000 cm from the first PlayerStart along +X. Each spawns an `AVeloxCharacter` possessed by `AVeloxDummyController`, which strafes along Y between +-`StrafeHalfWidth` (300 cm) at `StrafeSpeedScale` (1.0) of max ground speed through `AddMovementInput` / `SetLocalMoveInput` (server only) and logs its position every 2 s (`LogVelox`, Log). Reuses `M_Greybox_*` (run `create_movement_test_map.py` first on a fresh checkout), idempotent, asserts counts. Pass an absolute `-script=` path (a relative one resolves against the engine binaries dir). Smoke: `UnrealEditor-Cmd Velox.uproject L_CombatTest -game -nullrhi -unattended -nopause -nosplash -stdout -FullStdOutLogOutput`.

## Bot navigation in the map scripts (M4, ADR 0005 sections 3 and 4)

The server builds a Recast nav mesh at map load (`RuntimeGeneration=Dynamic`, `Config/DefaultEngine.ini`); nothing is baked or saved in the map. Every map script that bots should play on follows these conventions:

- **One `NavMeshBoundsVolume` over the whole map** (`nav_bounds(...)` helper). UE 5.8 has no working whole-world mode (`bWholeWorldNavigable` is not a config property), so without a volume no nav data is created. A volume spawned from Python gets the default 200 cm cube brush; the scripts scale it to `size / 200` and assert the resulting bounds.
- **`AVeloxNavLink` actors** (`unreal.VeloxNavLink`, `nav_link(...)` helper): the actor stands at the link start, `link_start` stays zero, `link_end` is the end relative to the actor (no rotation). Set `type` (`unreal.VeloxNavLinkType.JUMP_PAD | DROP | JUMP | JUMP_FAST | ROCKET_JUMP`), `jump_pad` for pad links, `both_ways` only for symmetric gap jumps, `required_speed_cm_s` for gaps. Snap radius 60 / snap height 100 are the class defaults (`link_snap_radius`, `link_snap_height`).
  - Every jump pad gets a `JUMP_PAD` link from the pad trigger centre on the floor to the landing point the author intends (the item / marker on the platform; `velox.bots.DumpPadLandings` on a server prints `AVeloxJumpPad::ComputeLandingPoint` next to the link end).
  - Every free platform edge gets a `DROP` link from 60 cm inside the edge (platform top) to the floor 150 cm outside, at the edge midpoint. Edges that face a wall closer than ~200 cm, a ramp's own edge, or a pad (the drop would land on it) get none.
  - Gap jumps: start 60 cm before the take-off edge, end 100 cm onto the landing platform; `JUMP` for gaps a bot clears at ground speed (500 cm), `JUMP_FAST` when strafe speed is needed (700 cm), no link beyond a bot's reliable speed (900 cm).
  - `ROCKET_JUMP` links (one in `L_ItemTest`, onto the 350 cm rockets platform): start on the floor 450 cm from the platform edge (run-up), end at the platform centre.
- The actor-count asserts include `navbounds` and `navlink`. Check a regenerated map headless: `UnrealEditor-Cmd Velox.uproject <Map> -server -nullrhi -ExecCmds="velox.bots.DumpPadLandings, velox.bots.DumpNav x y z x y z [Walk|Hop|Full]"` logs `VeloxNav built tiles= seconds= links= relevant_triggers=0`, the pad landings and the path points with `link=<type>` (`LogVeloxBots`).
- `L_ItemTest`: `Ammo.Rockets` stands on the rockets platform; its grid slot keeps the marker and a "moved" label so every other grid item keeps its position (one placed instance per definition, as `Velox.Items.ItemTestMap` asserts).

## Shared map library: `veloxmap.py` (ADR 0006 section 2)

`veloxmap.py` is the one place the map generators get their helpers from; `create_movement_test_map.py`, `create_combat_test_map.py` and `create_item_test_map.py` import it (`sys.path.insert(0, dirname(__file__)); import veloxmap as vm`), and `create_dm1_map.py` (task 05) builds on it. Module-level state covers the actor subsystem, per-kind `COUNTS`, loaded greybox materials and `ERRORS`; a script calls `configure()`, `greybox_materials()`, `rebuild_map()`, spawns, `assert_counts()`, `save_map()`, `raise_if_errors()`. Every actor spawned through a helper gets the tag `Layout:<name>` (the actor label unless `layout=` is given) so lint and audit output can name the layout record. The three test maps were regenerated once with these tags (task 03b, ADR 0006 E0.4) and the `.umap`s are committed.

Helpers: `box(name, center, size, material, kind, collide=True, tags=())`, `ramp`, `stairs`, `cylinder_marker`, `text_label`, `nav_bounds(center, size)`, `nav_link`, `drop_links`, `jump_pad` (+ `check_pads`), `pickup(definition_path, location, tags)`, `player_start(name, location, yaw)`, `clip_walls(half_x, half_y, height, ceiling_z)`, `set_kill_z(z)`, `static_sun_and_sky()`, `greybox_materials()`, `rebuild_map(path)`, `assert_counts(expected)`, `save_map()`, plus the generic `spawn(...)` and `tag_actor(...)`.

Regeneration (all with `-nullrhi -unattended -nopause -nosplash -stdout -FullStdOutLogOutput`, absolute `-script=` paths; run the movement map first on a fresh checkout because it creates the `M_Greybox_*` materials):
`UnrealEditor-Cmd Velox.uproject -run=pythonscript -script=$PWD/Tools/editor/create_movement_test_map.py ...` (then `create_combat_test_map.py`, then `create_item_test_map.py`, which also needs `create_item_content.py`).

## Map-independent generator (ADR 0008 section 1.2, task M7 P2)

`mapgen.py` holds the generator (formerly the body of `create_dm1_map.py`); every function takes the layout table as its first parameter `L`, `mapgen.bind(L)` returns a facade without it. Record types live in `maps/records.py`, tables in `maps/<slug>_layout.py` (`dm1_layout.py` imports the records). `create_map.py --map <slug> [--mode blockout|art] [--validate-only] [--golden check|write] [--selftest]` is the CLI (in the editor: `-script="<abs>/Tools/editor/create_map.py --map dm1 --mode blockout"`); `create_dm1_map.py` is a shim for `--map dm1` and `VELOX_DM1_MODE` is still honoured. `--golden check` (pure Python) compares `maps/golden_dump.py`'s output with `maps/golden/<slug>.json` byte for byte; `infra/ci/build.sh` runs it for every golden file before the engine is resolved, so it also runs without Unreal. The sections below describe DM1 as built before the split; `create_dm1_map.py` there now means `create_map.py --map dm1`.

## DM1 "Praesidium": `maps/dm1_layout.py` and `create_dm1_map.py` (ADR 0006 sections 2 and 3, task M5-05)

`maps/dm1_layout.py` is the declarative layout table (namedtuples and lists, no `unreal` import): rooms, solid boxes, wall strips with openings, stairs, the 15 degree ramp, the three pads, 35 items (with `disabled_in_modes`), 8 spawns, 16 nav links (task 06: 22 in the first blockout; the drops that face a blank wall or land on PadD were removed, DROP_OUT_TALL 350 for the tall ones), light placeholders (task 15), clip volumes, nav bounds, `MAP_ID`, `DISPLAY_NAME = "Praesidium"` (E0.5), `FLOOR_Z = 0`, `KILL_Z = -1000`. Its docstring has the top-down sketch.

`create_dm1_map.py --mode blockout` (default; the mode can also come from `VELOX_DM1_MODE`; `--mode art` raises "task 15") regenerates `/Game/Maps/DM1/L_DM1_Blockout` idempotently:
`UnrealEditor-Cmd Velox.uproject -run=pythonscript -script="$PWD/Tools/editor/create_dm1_map.py --mode blockout" -nullrhi -unattended -nopause -nosplash -stdout -FullStdOutLogOutput`
(needs `create_movement_test_map.py` for the materials and `create_item_content.py` for `/Game/Items`).

- Before touching the editor it validates the table in plain Python (`python3 -I Tools/editor/create_dm1_map.py --validate-only` runs only this): walkable widths >= 120, openings 240..400, room ceilings (atria 800, rooms >= 480, corridors >= 320), pad landing zones >= 300 x 300 with a simulated arc (same formulas as `AVeloxJumpPad`; the simulated landing must be within 60 cm of the authored landing and of the `JUMP_PAD` link end), rocket-jump clearance >= 900, spawns >= 10 m apart, <= 8 m (horizontal) from a weapon and without line of sight to Mega / RA, ammo 6..12 m from its weapon, the ADR item mix, Quad disabled in Duel, every item standing on a solid top.
- It then spawns everything with the `veloxmap.py` helpers, tags every actor `Layout:<record id>`, asserts the per-kind counts, sets `KillZ -1000`, one `NavMeshBoundsVolume`, perimeter + roof + per-room ceiling clip, and verifies that no actor carries `NavLintIgnore` (E0.2 b: forbidden on DM1).
- `veloxmap.configure(fill_nav_kinds=("floor", "wall", "platform", "step"))`: every solid that stands on the ground fills the nav underneath; `ramp`, `bridge`, `bridgewall` and `lintel` hang over walkable space and never do (E0.2 d). The ramp's void is sealed by stepped `A_Ramp_Fill_*` boxes (residual clearance < 60 cm).
- Gates: `infra/ci/navlint.sh /Game/Maps/DM1/L_DM1_Blockout` (`clusters=0` walk-in and isolated, `lowclear polys=0`), `infra/ci/fts.sh` (`FtDm1Reachability`, FT_DM1_Reachability), `velox.bots.DumpPadLandings` (each landing within 60 cm of its link end).
- Quad gating: `UVeloxItemDefinition::DisabledInModes` (`Velox.Mode.*` tags, set by `create_item_content.py`: the Quad lists `Velox.Mode.Duel`); `AVeloxPickup::BeginPlay` destroys such a pickup on the server before the item registry sees it (`VeloxPickupDisabled` log line).

Nav fill kinds and the lint baseline (task 03b, ADR 0006 E0.2 (d)/(e)): each test map passes `fill_nav_kinds` to `configure()` so solid boxes carry `fill_collision_underneath_for_navmesh` (no nav island inside them): `L_ItemTest` `("platform", "cross")`, `L_CombatTest` `("cover",)`, `L_MovementTest` `("platform",)`. Ramps are deliberately **not** filled anywhere: the fill under a thin surface deletes the floor nav beneath it and creates the walk-in class (the movement map's under-ramp floors); a ramp over a void is sealed with pawn-blocking boxes instead. The 100 cm slots north of the Mega and RA platforms of `L_ItemTest` are sealed with `<Item>_NorthFill` platform boxes. The report-only `navlint.sh` output of the three maps after 03b is the baseline in `docs/tasks/m5-map-characters/notes/03b-report.md`; regenerating a test map later must not add a cluster (any kind except `edge`) beyond it.
