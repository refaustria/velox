# Design review — M2 task 01 `gas-foundation` (architect, 2026-10-25)

**Scope reviewed:** `Source/Velox/Combat/*` (new in d52e3b9), `GameModes/VeloxPlayerState.*`, `GameModes/VeloxPlayerController.*`, `Character/VeloxCharacter.*` (ASC init paths), `Core/VeloxGameplayTags.*`, `Movement/VeloxMovementComponent.*` (`EVeloxKnockbackSource`), `Config/DefaultGame.ini`, `Tests/VeloxCombatTests.cpp` — against ADR 0003 §1–§2 and ADR 0002 A17. Engine claims verified against `/opt/UnrealEngine-5.8` GameplayAbilities and Engine source (line numbers below).

**Verdict: accept with one correctness fix before task 04 (B2, armor constant) and one call-site change before task 04 (B6, ability input timing).** Nothing blocks task 02 or 03. The structure is the ADR's: metas → commit in `PostGameplayEffectExecute` → one knockback entry point, grant-once on the PlayerState, C++ GEs, Lyra three-list input. Prediction/replication safety is sound (details in §3).

ADR 0003 gained amendments **B1–B9** (end of the ADR). Task files 02, 04, 05, 06 carry the resulting instructions under "Review notes".

## 1. Rulings on the implementer's points

| # | Point | Ruling |
|---|---|---|
| 1 | Settings referenced from `AVeloxPlayerState` config, not the GameMode | **Accepted** (B1). Clients need clamps/caps. Preload in `PostInitializeComponents` instead of lazy `LoadSynchronous` (first load would happen inside `PreAttributeChange` during client replication). GameState override in M3. |
| 2 | Armor save `ceil(D × 0.6667 − 1e-3)` | **Rejected — both the constant and the tolerance** (B2). Q3 uses `ARMOR_PROTECTION 0.66` with `ceil` in double math; the ADR's 0.6667 was wrong. 100 vs 100 armor must give 66 armor / 34 health; 50 (self-rocket) → 33/17. Use `int32 ArmorProtectionPercent = 66` and `Save = min(Armor, Damage, (Damage × 66 + 99) / 100)` — exact integer ceiling, no float, no tolerance. |
| 3 | Minimum 1 damage after self halving | **Confirmed** (B3), and it applies to every hit, not only self: Q3 `if (damage < 1) damage = 1` follows the halving unconditionally. Extension: Q3 radius damage calls `G_Damage` with `(int)points == 0` inside the radius → 1 damage, no knockback. `Apply` must not early-out for `Damage == 0` (only `< 0`). |
| 4 | Decay period fixed 1 s | **Confirmed** (B4). Q3 `ClientTimerActions`, 1000 ms residual. Not tunable. |
| 5 | `SpawnAmount` standing in for `SpawnLoadout` | **Accepted as interim** (B5). Task 04 deletes it; `MakeSpawnInitSpec` derives ammo from `SpawnLoadout`. |

## 3. Checked and found correct (no change)

- **Clamping.** `PreAttributeBaseChange` and `PreAttributeChange` both round and clamp; `SetNumericAttributeBase` → `SetAttributeBaseValue` (base clamp) → `InternalUpdateNumericalAttribute` → `SetNumericValueChecked` (current clamp), so base and current agree and stay integral. Health clamps to `HealthHardCap` (not `MaxHealth`) — right for Q3 (megahealth to 200, decays to 100). Armor to `MaxArmor` (set before Armor in `GE_SpawnInit`). The constructor's `GetDefault<UVeloxCombatSettings>()` inside a CDO constructor works (tests pass) but is fragile at module-load order; leave it, `GE_SpawnInit` overwrites anyway.
- **Execution ordering and the commit.** The engine applies an execution's output modifiers in array order (`GameplayEffect.cpp:3293–3301`) and calls `PostGameplayEffectExecute` for each via `InternalExecuteMod` (l.4112–4131) regardless of magnitude — so the commit on `IncomingDamage` (written last) always fires, also for armor-only or protected hits (`OnDamaged` broadcast with zero loss, as the header promises). `SetIncomingX(0.f)` resets base and current.
- **Capture semantics.** Target `Armor` is captured at application (`CaptureAttributeDataFromTarget`, `AbilitySystemComponent.cpp:1109`) per spec; two damage GEs in one frame are applied sequentially and the second captures the armor the first already committed. Snapshot flag is irrelevant for Instant GEs. Armor has no duration modifiers, so the captured aggregate equals the base.
- **Death while another execution is queued.** Handled by the `Velox.State.Dead` check in the execution *provided* task 06 applies `GE_Dead` synchronously inside `OnOutOfHealth` (B8). The `bOutOfHealth` latch prevents a second `OnOutOfHealth`; `PostAttributeChange` resets it when Health rises (SpawnInit).
- **`AddKnockback(Server)` from the attribute set.** Authority enforced inside `AddKnockback` (`VeloxMovementComponent.cpp:226–231`), simulated proxies return early (l.232–236), avatar null → no knockback, dead target → zero from the execution. Exactly one entry point, chained channel (A17) — correct for every server impulse.
- **Input routing vs Lyra.** Held → `WhileInputActive` not-active specs; pressed → `InputPressed = true`, forward to active, else activate `OnInputTriggered`; activate after the press pass; released → `InputPressed = false`, forward if active, release not filtered. Identical to Lyra's `ProcessAbilityInput`. `AbilitySpecInputPressed/Released` invoke the replicated generic events with the instance's activation key (Lyra). `CanRouteInputToSpec` hook for the task-04 fire filter is in place. `ClearAbilityInput` on avatar change: good.
- **`UVeloxGameplayAbility` defaults.** `InstancedPerActor + LocalPredicted + ReplicateNo + ClientOrServer` = Lyra; right for weapons (one instance keeps `NextFireTime`, activation predicted, no ability-state replication). `bServerRespectsRemoteAbilityCancellation = false` → `RemoteEndOrCancelAbility` (`AbilitySystemComponent_Abilities.cpp:2163`) ignores the client's `ServerEndAbility`, so a client cannot cancel the server's shot resolution. Keep.
- **Grant-once / respawn.** `PossessedBy` → `InitAbilityActorInfo` → `OnPawnPossessed` → grant once → `GE_SpawnInit`; `UnPossessed` clears the avatar only if this pawn is the avatar (guard present); `OnRep_Controller` refreshes only if avatar (guard present). The Effects test covers kill → unpossess → new pawn → no re-grant, one decay effect.
- **Decay.** Periodic timers are set wherever the GE is applied (no authority gate in `ApplyGameplayEffectSpec`, l.4496), but `GE_SpawnInit` is server-only and clients receive the active GE by replication without timers — fine. `bExecutePeriodicEffectOnApplication = false` → first tick at 1 s (test "no decay at application").
- **`UVeloxAbilitySystemGlobals` config quirk.** `UGameplayAbilitiesDeveloperSettings::OverrideConfigSection` → `/Script/GameplayAbilities.AbilitySystemGlobals` (`GameplayAbilitiesDeveloperSettings.h:125–131`); the ini section and the comment are right; the test asserts `UAbilitySystemGlobals::Get().IsA<UVeloxAbilitySystemGlobals>()`.
- **`FVeloxGameplayEffectContext`.** `Duplicate` re-adds the hit result, `NetSerialize` chains the base, `TStructOpsTypeTraits` set; `Get()` checks `IsChildOf`. Fine.
- **`velox.combat.TestDamage` / `TestRespawn`.** `#if !UE_BUILD_SHIPPING`, PIE authority-world lookup, world damage built on the victim's own ASC with `bSelf` explicit — correct.
