Engine claims checked in `/opt/UnrealEngine-5.8` where a ruling depends on them (`AController::Reset` Controller.cpp:442, `AAIController::Reset` AIController.cpp:106, `APawn::Reset` Pawn.cpp:934). No soak was run (machine busy); the HasteRun 5/5, ItemRun 3/3 and the 05 evidence are taken from the reports.

**Verdict: accept all four designs. One must-fix (items, small) and three should-fix items go to task 13 (dev, ~2 h). Nothing blocks 08/10/12.** The three places where a wrong early decision would have been expensive are right: (1) Haste lives in the owner's move-time domain, chained through the A18 snapshot and now also carried by acks, evaluated at the same stamp on both ends — the implementer's signed-time-left wrap rule (D1) is correct where the ADR's `!IsMoveTimeDue` was wrong, and keeping the end time across a natural expiry (D2) is what makes the expiry exact; (2) the pickup is a server grant with event-only client prediction, nothing client-supplied reaches an attribute; (3) the phase machine is a world-free table fed from the world, with `ResetLevel` as the restart. ADR 0004 gains amendments **C1–C10**, ADR 0002 gains **A37** (the response container now carries Velox fields on acks; the Haste boundary is not an event move).

## 1. Rulings

| # | Departure / question | Ruling |
|---|---|---|
| D1 (03) | Wrap rule replaced: signed time-left `End − t` reduced into `(−P/2, P/2]`, `End` normalised into `(0, P]`, remaining clamped to `0.45 P`, stale ends (`> P/4` past) dropped by non-replayed moves | **Accepted, ADR corrected (C1).** The engine's reset subtracts exactly `MinTimeBetweenTimeStampResets` on both ends (`UpdateTimeStampAndDeltaTime`, `VerifyClientTimeStamp`), so the stamp domain is modular with period `P` and the signed modular difference is the exact rule. The ADR's `!IsMoveTimeDue(End, t, P)` is "active iff `t < End` and `End − t ≤ P/2`", which turns false for every end the moment `t` drops by `P` — a dropped powerup at each reset, as the implementer says. The `0.45 P`/`0.25 P` margins keep the three regions (active, inactive, stale) disjoint for every reachable duration (`HasteScale` covers the wrap cases). |
| D2 (03) | `End` kept on natural expiry, zeroed only on premature removal (`FGameplayEffectRemovalInfo::bPrematureRemoval`) | **Accepted (C1).** The GE expires on server world time, the move timeline on client stamps; clearing at the GE's expiry would cut the in-flight moves the server has not processed yet → one correction per Haste. ## 2. Defects, ranked (file:line → fix)

1. **Must-fix (F1, task 13) — a possessed AI pawn standing in a pickup takes it during `ResetLevel`.** `Items/VeloxPickup.cpp:605–630` (`Reset` → `ScheduleInitialSpawn` → `CheckOverlappingPawns(true)` synchronously at :626–629). `AGameModeBase::ResetLevel` resets controllers first, then every actor in iteration order: `APlayerController::Reset` unpossesses (the human pawn has no PlayerState → `IsPawnEligible` false → silent), but `AController::Reset`/`AAIController::Reset` (Controller.cpp:442, AIController.cpp:106) do **not** unpossess, and `APawn::Reset` (Pawn.cpp:934) destroys the pawn only when its own turn comes. A dummy — or an M4 bot camping Mega/RA — whose pawn is iterated *after* the pickup passes `TryPickup` with a valid PlayerState and ASC, is granted the item, and is destroyed a few actors later; the item is then down for its full respawn at Live start (and with a powerup, the 30–60 s initial delay is *replaced* by the take). Fix: `Reset()` schedules the standing-pawn check for the next tick (`GetWorldTimerManager().SetTimerForNextTick(…CheckOverlappingPawns(true))`) — by then every pawn of the old round is destroyed and the restarted ones have spawned; `ServerRespawn` (timer-driven, :584) is unaffected. Test: extend `Velox.Items.Pickup` or `FT_ItemPickup` with "pawn inside the trigger, `ResetLevel` → item still available after the reset, taken on the next tick only if a live pawn stands there".
2. **Should-fix (F2, task 13) — spurious take event for late joiners (01-d).** `Items/VeloxPickup.cpp:723–759` (`HandleReplicatedState`, `TakeCount != SeenTakeCount` → `OnPickupTaken` broadcast), `:212–216` (client baseline in `BeginPlay`). Rule (C10): on the client, a take whose age `ServerNow − (RespawnServerTime − RespawnSeconds × ItemRespawnScale)` exceeds `UVeloxCombatSettings::PickupTakeEventMaxAgeSeconds` (new, 1.0 s) updates `Seen*` and the placeholder but is **not** broadcast as an event (no "X took Mega" for a joiner; the timer list reads `GetTimeUntilRespawn()` directly and is unaffected). Server-side broadcasts are untouched (M4 bots). Weapon-stay items (respawn 0) never carry an age — they are only ever broadcast live.
3. **Should-fix (F3, task 13) — ready cleared on a countdown abort (05-a).** `GameModes/VeloxGameModeMatch.cpp:297–309` (`bKeepReady` only for Warmup → Countdown). Rule (C5): clear `bReady` on entering Live, on entering PostMatch and on leaving PostMatch; keep it on Warmup ↔ Countdown in both directions. `Velox.GameMode.MatchRules` is unaffected (pure table); add a row to the match-state headless check: Duel A+B ready → Countdown, B un-readies → Warmup with A still ready, B readies → Countdown again without A pressing.
4. **Should-fix (F4, task 13) — a client that connects or joins during PostMatch is not in the intermission.** `GameModes/VeloxGameModeMatch.cpp:454–468` sends `ClientEnterIntermission` to the controllers present at the transition only; `GameModes/VeloxPlayerController.h:92` `IsInIntermission()` is `bInIntermission` alone. Fix: `IsInIntermission()` returns `bInIntermission || (GameState phase == PostMatch)` on every machine, and `PostLogin` during PostMatch calls `EnterIntermission` + `ClientEnterIntermission` for the newcomer with the same view target. 08's forced scoreboard keys on the phase anyway (`OnPhaseChanged`); this closes the view-target gap.
5. **Minor (no task) — `HasteRun` is not in `nettest.sh`'s default script list** although ADR §10 lists it with `ItemRun`. Task 13 adds it (and the README line); the "idle machine only" rule stands. Also add `VeloxPowerupMoveTimes`/`VeloxHasteState` to the README's log-line table.
6. **Minor (no task) — `UVeloxRegenExecution` logs at `Log` once per second per regenerating player** (`Items/VeloxPowerupEffects.cpp:162`). Fine for M3 evidence; M7's perf pass demotes it to `Verbose` like `VeloxDecay`.

Checked and found correct (recorded so the next reviewer does not re-derive them): the move's scale is computed at its end stamp on both ends (`PerformMovement` → `GetPowerupClockNow` = `ClientData->CurrentTimeStamp` after `UpdateTimeStampAndDeltaTime` on the client, `LastMoveAutonomousTimeStamp` on the server and in replays), so a pickup overlapping inside move N leaves N at × 1 and N+1 at × 1.3 on both ends; `bSavedHasteActive` uses the same stamp (`SetMoveFor` after the advance); the ack path applies live values only when no correction is pending (the pending replay uses the snapshot); packets are ordered per connection, so a stale ack cannot overwrite a newer end; `SerializeOptionalValue<float>` costs one bit per field while 0 and 64 bits per response while a powerup is active (`PowerupResponseSerialize`); `GetMaxSpeed` is consistent with the sim on every role (simulated proxies hold no end times → × 1); the listen host and bots run in the world-time domain on both the grant and the evaluation side, and their projectile Quad comes from the tag at the explosion (`LaunchServerShot` local branch), so no domain mix; `ModifyActiveEffectStartTime` → `OnDurationChange` → `OnTimeChanged` (verified by 02 at GameplayEffect.cpp:5674) re-anchors the end on an extension; per-effect delegates bound by a previous life are filtered by `IsPowerupAvatarOf`; the Battle Suit order (knockback → radius returns → × 0.5 → self × 0.5 → min 1 → armor) is `G_Damage`'s; `UVeloxHealthSet::ClampAttribute` caps at `HealthHardCap`, so Mega stacks to 200 through `GE_Heal`; the pickup's dormancy flush precedes every replicated write; `RequestJoin`'s `NumSpectators`/`NumPlayers` adjustments mirror `AGameMode::PostLogin`'s `MustSpectate` counting; `RestartMatch` restarts every pawn-less active controller itself, so the Countdown → Live path (match state already `InProgress`) does not depend on `HandleMatchHasStarted`.

Accepted residuals (not defects): a powerup granted *outside* a move (cheat, standing retake from the respawn timer) anchors its end at the last processed stamp, ≤ one net update earlier than the client's "now" — invisible; the HUD's remaining time comes from the ASC and may read 0 while movement is still hasted for ≤ RTT; `EndMatch()`/`SetMatchState(InProgress)` cycle `AGameSession::HandleMatchHasStarted/Ended` every match — M6 checks what the online subsystem's `StartSession`/`EndSession` do with that; `OnRep_Phase` does not fire for a second Timed overtime (same enum value) — the HUD reads `PhaseEndServerTime` per frame.
