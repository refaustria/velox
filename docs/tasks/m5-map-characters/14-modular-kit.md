# 14 — Modular environment kit: Blender script, import with lightmap UVs, materials

**Milestone:** M5 Map + characters
**Agent:** dev
**Status:** done
**Depends on:** 11 (`export_common.py`, `import_art.py`); ADR 0006 §2, §5, §8 and **E0.5** (decisions 32 and 34: low-poly flat-shaded, **concrete and steel bunker** — the kit's palette and trims follow it; map display name `Casemate`)

## Goal
≤ 25 kit pieces on the 400 cm module that can replace every box the DM1 layout uses: floor tile, wall 400 × 400 (plain, with trim, with door frame 300 and 400), half wall, pillar, ceiling tile, 15° ramp (400 long), stairs (20 cm risers, 400 run), ledge edge/railing stub, bridge segment, jump-pad base ring, item pedestal, light fixture (emissive), skirting/trim. Each piece has UV0 for materials, UV1 lightmap (generated at import), ≤ 600 tris, and one of ≤ 8 material instances of `M_Kit_Master`. Palette follows the style guide (V ≤ 0.5, S ≤ 0.25).

## Scope — files/modules the agent may touch
- `Tools/blender/kit.py` (new), `Tools/editor/import_art.py` (`--kit <dir>`: lightmap UV generation, resolution per piece, collision `NoCollision`), `Tools/editor/create_cosmetics_content.py` or a new `create_kit_materials.py`, `ArtSource/Kit/kit.blend`, `ArtSource/Export/SM_Kit_*.fbx`, `ArtSource/Textures/T_Kit_*.png` (≤ 1024², ≤ 6 textures), `Content/Environment/Kit/**`, `Content/Environment/Lighting/TC_Sky_DM1` (LFS), `docs/art/kit-spec.md`

## Relevant ADRs / references
- ADR 0006 §2 (kit replaces boxes; clip-first; protrusion rule ≤ 5 cm into walkable space), §5 (lightmap resolutions 128/64/32, `bGenerateLightmapUVs`, `MinLightmapResolution 64`, `DstLightmapIndex 1`), §8 (budgets: ≤ 25 meshes × ≤ 8 materials), style guide (task 11)

## Acceptance criteria
- [x] `kit.py` emits every piece listed above with exact module dimensions (floor 400 × 400 × 20 top at Z 0; wall 400 × 20 × 400; ramp rises 107 cm over 400 — 15°; stairs 5 × 20 cm risers over 400 run, matching the layout's `stairs` record), pivots at the piece's floor-level corner the generator expects (documented in `kit-spec.md`), hard edges only, no n-gons, ≤ 600 tris; textures generated procedurally in Blender (noise + grid) and baked to PNG ≤ 1024².
- [x] `import_art.py --kit`: `bGenerateLightmapUVs`, `DstLightmapIndex 1`, `MinLightmapResolution 64`, per-piece `LightMapResolution` (floor 128, wall 64, trims/pillar 32, bridge 64) set on the static mesh, `NoCollision`, `--verify` asserts UV channel count = 2, tri budget, one material slot, 25-piece cap.
- [x] Materials: `M_Kit_Master` (base colour tint × texture, roughness constant, optional emissive for the fixture), ≤ 8 `MI_Kit_*`; the palette assertion from the style guide runs in the script (no instance with V > 0.5 or S > 0.25 except the emissive fixture).
- [x] `TC_Sky_DM1`: a 128 px cubemap generated by script (gradient sky, neutral grey ground) imported as `TextureCube`.
- [x] `docs/art/kit-spec.md`: piece table (name, size, pivot, lightmap res, material), texel density, what the human may replace.
- [x] The pieces are produced by the Blender run on the VM (ADR 0006 E0.5). `import_art.py --kit --fixture` (`/Engine/BasicShapes/Cube` exported, imported through `--kit` with generated lightmap UVs, verified, deleted) stays as the self-test of the import path.

## Notes / outcome

Done (branch `m5-map-characters`). 18 pieces, 648 tris total (max 96 per piece), 8 `MI_Kit_*` of `M_Kit_Master`, 5 textures (4 x 512, 1 x 256), `TC_Sky_DM1` 128 px cube. Piece table, pivots and texel density: `docs/art/kit-spec.md`. Reproduce: `Tools/blender/kit.py` -> `Tools/editor/create_kit_materials.py` -> `Tools/editor/import_kit.py --kit ArtSource/Export --verify` (`--fixture` = import-path self-test).
Deviations: (1) the `--kit` path lives in `Tools/editor/import_kit.py` instead of `import_art.py`, which does not exist on this base (task 11 creates it; it should dispatch `--kit` to `import_kit.run`). (2) No dependency on 11's `export_common.py`: `kit.py` is self-contained. (3) The Blender Y axis is mirrored in `make_object` because FBX import maps Blender +Y to Unreal -Y; the verify step compares imported bounds with the manifest. (4) The fixture cube already has a lightmap UV set, so the fixture asserts "source UV count + 1" rather than 2. (5) UV channel count is read from render data (`get_num_tex_coords`), `EditorStaticMeshLibrary.get_num_uv_channels` returns 0 for built meshes. (6) The full `infra/ci/build.sh` was not re-run (no C++ change; the VeloxEditor target built clean on this branch before the work).
