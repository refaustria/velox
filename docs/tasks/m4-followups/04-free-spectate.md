## Goal
A dead human free-flies through the arena until the respawn instead of watching the corpse: the engine's spectating state with a project spectator pawn (`AVeloxSpectatorPawn`, client-local, unreplicated), selected per mode by `UVeloxGameModeDefinition::DeathCamera` (default `FreeSpectate`; `Corpse` keeps today's path). The server clamps the client-synced view point into the arena; a dead player keeps the player's information rules (no spectator item timers, player rows); fire/jump after `MinRespawnDelay` respawns as today; bots, dummies, forced respawn and the intermission keep working. B8's death order is preserved.

**2026-10-31, dev-hard: implementation (after the architect's ruling on fact (c), ADR 0004 C11 as amended; death-camera note = ADR 0003 B43).**

- *Model.* `CompleteDeath` keeps B8's order: corpse state, `UnPossess`, `VeloxDeath step=5`, then `AVeloxGameMode::NotifyControllerDied(Controller, Corpse)`. For player controllers that reads `GetDeathCamera()`: the definition's `DeathCamera` (class default `FreeSpectate` without a definition), or the non-shipping cvar `velox.match.DeathCamera` (-1 = asset, 0 = Corpse, 1 = FreeSpectate). Corpse calls `SetViewTarget(Corpse)`; FreeSpectate calls `AVeloxPlayerController::BeginDeathSpectate`. Either way it logs `VeloxDeath step=6 spectate=`. AI controllers take neither branch. Without a Velox game mode the old `SetViewTarget(this)` stays. `HandleDeath` stores the eye (`GetPawnViewLocation`) and the control rotation on the controller before the corpse drop.
- *Controller.* `BeginDeathSpectate` (server) seeds the clamp's last accepted point (and `LastSpectatorSyncLocation`) with the death eye at the server time, calls `ChangeState(NAME_Spectating)`, then `ClientBeginDeathSpectate(Eye, Rot)`. The RPC is skipped for local controllers. The `BeginSpectatingState` override places the engine-spawned spectator pawn at the eye/rotation and logs `VeloxSpectate begin`. A `ChangeState` override ends a death spectate on leaving `NAME_Spectating` (`EndDeathSpectate`: Playing = respawn, Inactive = intermission; `EndPlay` = logout), with `end_server ... syncs clamps spectator_pawn` on the authority and `end reason=` on the owning client. `SetPawn(null)` arriving after the client RPC keeps the view on the spectator pawn. Without that, the engine's `AutoManageActiveCameraTarget(this)` would take it. `EnterIntermission` switches a death-spectating controller to `Inactive` first (plus `ClientGotoState(Inactive)` for a remote one), before the view target is set.
- *Clamp.* `ServerSetSpectatorLocation_Implementation` passes `VeloxSpectate::ClampViewPoint` to `Super`. The clamp applies, in order: the speed step from the last accepted point with `Dt` floored at `DeathSpectateSyncDtFloorSeconds`; the nav-bounds box plus margin; `KillZ + 50`. A NaN request falls back to the last point. Clamps are counted and logged (1/s). The engine's 4 Hz send is untouched. The nav-bounds AABB is cached on first use (`GetSpectateBounds`) instead of in `InitGame`: brush bounds need registered components (log `VeloxSpectate bounds volumes=1` on L_CombatTest, box +-2200 / -200..800).
- *Pawn.* `AVeloxSpectatorPawn` (`NotPlaceable, Transient`; `bReplicates` untouched): `bAddDefaultMovementBindings = false`, `UVeloxInputComponent`, bindings from `AVeloxPlayerController::GetInputConfig()`. That is the last possessed character's pawn-data `InputConfig`, or `UIInputConfig` before any possession (a spectator from the start). Move (view-yaw plane), Look (shared `VeloxSettingsMath::MouseDeltaToDegrees`, already factored), Jump = up, Crouch = down (held state, applied per tick). Speed/acceleration/deceleration come from the PlayerState's combat settings in `PossessedBy`. `?SpectatorOnly=1` spectators get the same pawn, but the engine spawns them a plain `APlayerController` (`AGameModeBase::SpawnPlayerController`: `ReplaySpectatorPlayerControllerClass`, GameModeBase.cpp:743), so for a non-Velox controller the pawn keeps the engine's default spectator bindings (`bAddDefaultMovementBindings`), as `ASpectatorPawn` did; BotDuel `--repeat 1` PASS afterwards.
- *Final settings* (`UVeloxCombatSettings`, a data asset, Category Respawn; `DefaultGame.ini` not changed because the class is not a config class): `DeathSpectateSpeedCmS 1200`, `DeathSpectateAccelerationCmS2 6000`, `DeathSpectateDecelerationCmS2 8000`, `DeathSpectateBoundsMarginCm 300`, `DeathSpectateSyncSpeedScale 3.0`, `DeathSpectateSyncDtFloorSeconds 0.0167`. `UVeloxUISettings::DeathSpectatePrompt` = "free look - FIRE to respawn" (em dash), shown until `MinRespawnDelay`, then the existing respawn prompt.

Pinned by `Velox.GameMode.ModeDefinitions`: Duel 5, FFA null / default asset 20, CDO 20, `FreeSpectate` both, and a drift guard (`TFieldIterator` over `UVeloxCombatSettings`' own properties, `Identical_InContainer` Duel vs Default except `ForceRespawnDelay`). ADR 0004 C11 already carries the decision line (architect, 8ec36f0).
- *Soak hooks.* `serverKill` row and `ServerKillSelfTest` (non-shipping, environment damage). A run that killed its pawn quits only 1.5 s after it saw the respawned pawn (`VeloxNetSoak event=respawn_seen`; 60 s timeout = exit 1). Deviation from C11 (2): `-ini:Game:[/Script/Velox.VeloxCombatSettings]:ForceRespawnDelay=4` cannot work because the settings are a data asset, not a config class. The ruling's fallback is used instead: non-shipping cvar `velox.combat.ForceRespawnDelay` (server `-ExecCmds`), echoed by `VeloxRespawn waiting ... forced in 4.00 s`. nettest rule detail: the new pawn's `VeloxShotSeqReset` can come *before* the client's `end reason=respawn`, because the pawn initialises with the PlayerState's ASC before `ClientRestart`. **What a dead player can see (for the human's Duel decision):** while dead the player flies freely, client-side only, at up to 12 m/s (Move/Look, jump = up, crouch = down). Clip walls and ceilings contain the flight; pawns and pickups do not block it. Relevance comes from the synced view point, which lags at most about 0.25 s plus half an RTT. On Velox maps every pawn is inside the 150 m cull distance anyway, and pickups are always relevant. In practice the dead player sees everything a living player at that point would: enemy positions, their movement and fire, and which items are up (by looking at the pickups). They do *not* get the spectator item-timer list, and they stay a player on the scoreboard. In Duel this scouting window now ends after 5 s at most (forced respawn; earlier with FIRE after 1.7 s); in FFA after 20 s.
