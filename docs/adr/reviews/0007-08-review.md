## Verdict: APPROVE WITH FOLLOW-UPS

Keep c4a112f. **No item-timer datum leaves the server toward a non-entitled connection through any path checked** (F9, F10 below). The design is the ADR's; the one deviation (`ItemIndex` as the replicated key) is accepted and recorded. Two things must happen before the branch reaches `m6-online`, neither a code defect of this task: the merge in F1 and the one-line index change in F2. The rest are small follow-ups for a `dev` task.

### F2 — `ItemIndex` 0 is both the first pickup's key and every client's "not received yet" value (low; fix with the merge)

`Source/Velox/Items/VeloxItemRegistrySubsystem.h:112` `NextItemIndex = 0`; `VeloxItemRegistrySubsystem.cpp:63` hands out 0 first; `VeloxPickup.h:198` and `VeloxPlayerState.h:31` default to 0. Two consequences:

(a) On a client, a pickup whose initial bunch has not arrived yet still answers `GetItemIndex() == 0`, so `AVeloxPickup::GetTimeUntilRespawn()` (`VeloxPickup.cpp:193`) and `UVeloxHUDViewModel::UpdateItemTimers` (`VeloxHUDViewModel.cpp:453`) read the **first** pickup's entry for it. The window is the join itself (startup `DORM_DormantAll` actors are considered and replicate once — `NetDriver.cpp:5369` skips only `DORM_Initial` — then go dormant), so today it is a sub-second HUD glitch for a spectator only. It becomes a wrong number the day anything spawns pickups after join.

(b) The baseline rule needs the first bunch to **carry a property**: `PostNetReceive` runs only when `bHasReplicatedProperties` (`DataReplication.cpp:1602`). Today every placed pickup's open bunch carries `Definition` (the CDO's is null) and, for all but one, `ItemIndex`, so the rule fires at join. A pickup placed from a Blueprint subclass whose CDO already holds the `Definition`, with index 0, would open its channel with an empty bunch, never run `PostNetReceive`, and its first **take after the join** would be swallowed as the baseline. Not reachable with today's content; cheap to make unreachable.

*Fix (one line + one assertion):* `NextItemIndex = 1`; 0 means "no index". `FindPickupByIndex(0)` returns null; `GetItemTimer(0)` is never consulted (`GetTimeUntilRespawn` returns −1 and the HUD shows no clock for an index-0 pickup). Add to `Velox.Items.Replication`: "the first registered pickup has index 1". Also log a `Warning` once when `NextItemIndex` wraps to 0 (cheat-spawned pickups in a long editor session).

### F3 — `VeloxViewRefused` at `Log` level is reached by every honest fire press during the death camera (low)

`VeloxPlayerController.cpp:168`. Engine `APlayerController::StartFire` (`PlayerController.cpp:3269–3271`) sends `ServerViewNextPlayer()` for any `NAME_Spectating` controller with `bPlayerIsWaiting == false` — that is the death camera (C11). A human who mashes fire while dead produces one server log line per click; the evaluators count only `Error:` so nothing fails, but a line that reads like an anomaly marker must not be the honest path. *Fix:* `Verbose`, or `Log` once per spectate per controller, or keep `Log` and add `reason=fire|rpc` by checking whether the caller is `ServerViewNextPlayer`/`ServerViewPrevPlayer`. The refusal itself is right (F8).

### F4 — Two readers of the client-side timer rule (low)

`VeloxHUDViewModel.cpp:438–455` re-implements the client branch of `AVeloxPickup::GetTimeUntilRespawn()` (`VeloxPickup.cpp:193–213`): local PlayerState lookup plus `ServerNow`. *Fix:* the HUD calls `Pickup->GetTimeUntilRespawn()` and treats `< 0` as "unknown" (no clock, keep the "taken by" row); the scoreboard sort (`VeloxScoreboardFormat.h:175`) already handles 0. One rule, one place.

### F5 — Entitlement writers and push points: complete for M6, record the invariant (info)

Both `bOnlySpectator` writers push: `?SpectatorOnly=1` (engine `InitNewPlayer`) and the mode-full `StartSpectatingOnly()` (`VeloxGameModeMatch.cpp:124`) precede the `PostLogin` push (:136); `RequestJoin` pushes after `SetIsOnlyASpectator(false)` (:537–541); `Logout` clears (`VeloxGameMode.cpp:502`); `Reset` rebuilds (:173); `RefreshModeRules` rebuilds on a rule change. There is no player → spectator-only path in M6 (grep: no other writer). *Rule for the ADR:* every future writer of `bOnlySpectator` (an M7 `spectate` command, team switch) calls `PushTimersTo` in the same function; `HandleItemTimerChanged`'s "clear a stale set" branch (`VeloxItemRegistrySubsystem.cpp:150–155`) is the safety net, not the mechanism.

### F6 — Ruling on non-unique player names on a listen host (low; tooling)

Facts: the host and the remote client both logged in as `Player` because both use this machine's nickname and the branch lacks 07's `ChangeName` dedupe; on `origin/m6-online` `AVeloxGameMode::ChangeName` (`VeloxGameModeMatch.cpp:156–186` there) dedupes against every other PlayerState, and the host logs in through `InitNewPlayer` like any client, so after F1 the client is `Player (2)`. Ruling:

1. **No new server-side uniqueness enforcement** — 07's dedupe is it (ADR 0007 §5.2).
2. **Do not put the `PlayerId` into `VeloxPlayerLabel`.** It is also a UI string (`Timer.TakenBy`, `SpectatorNames`) and every nettest evaluator keys on `player=<name>`.
3. **Keep `local=`.** It states a listen-only fact no name can.
4. **Follow-up (dev, small):** the per-player server lines evaluators key on gain a separate `pid=<PlayerId>` field (`VeloxItemTimerEntitlement`, `VeloxItemTimerPush … to=[name#pid,…]`, the client's `VeloxItemTimers`), and the ItemGate evaluator matches by `pid` (the client reads its own replicated `PlayerId`). Reason: `kv()` (`nettest.sh:462`, `(\w+)=(\S+)`) truncates any name containing a space — `Sanitize` keeps single spaces and `Dedupe` produces `Player (2)` — so `player=Player (2)` parses as `Player` on both the client and the server lines and the listen round after F1 will pass **by coincidence**. Apply the same to other evaluators when they are next touched.

### F7 — Replays: owner-only timers are not recorded by the classic demo driver (info, for the M7 replays ADR)

`UActorChannel::ReplicateActor` sets `RepFlags.bNetOwner = (Actor->GetNetConnection() == Connection …)` (`DataChannel.cpp:3812`); a demo connection never owns a PlayerState, so a server-side demo contains **no** `ItemTimers` — no leak through distributed demos, and no timers for the M7 replay viewer either. The M7 option is `COND_ReplayOrOwner` on `ItemTimers` (post-hoc demos fine; a live-streamed server demo would then leak and needs a delay). Decide there, not here; add to ADR 0007 "Deliberately deferred".

### F8 — `ViewAPlayer` gate closes F1.2's note correctly (info)

`GetNextViewablePlayer` (`PlayerController.cpp:3212–3227`) breaks on the first PlayerState with a pawn that `CanSpectate` accepts and otherwise returns the last iterated entry, so overriding `CanSpectate` alone would still retarget a dead player's view; the `ViewAPlayer` override is the right layer and covers `ServerViewNextPlayer`, `ServerViewPrevPlayer` and `StartFire`'s path. `CanSpectate_Implementation` (`VeloxGameModeMatch.cpp:177–186`) additionally refuses spectator targets (incl. the listen host's spectator PlayerState) and self. The world-free rule `VeloxSpectate::MayViewOtherPlayers` is where a future "spectators may follow" mode toggle belongs. Note for the deferred follow-cam: a spectator-only client already **can** follow players today through the engine's `StartFire` → `ServerViewNextPlayer` — the ADR's "deferred" item is the UI and the camera, not the permission.

### F9 — Leak audit (info, passed)

- Pickup rep layout: `bAvailable`, `TakeCount`, `LastTakenBy`, `Definition` (initial), `ItemIndex` (initial); `RespawnServerTime` is no `UPROPERTY` (unit row asserts both). `GetTimeUntilRespawn()` on a client reads only the local owner-only entry (−1 otherwise); the only client-visible callers are the HUD (reads the entry directly) and non-shipping cheats/logs. `VeloxBotItemRouting.cpp:191` runs on the server.
- No RPC carries a time. `OnPickupTaken`/`OnPickupRespawned` carry none. `LastTakenBy` names the taker only (ADR 0004 §1 keeps it for everyone).
- `AVeloxPlayerState::ItemTimers` `COND_OwnerOnly` + push (unit row); bots have no connection (`IsABot()` short-circuits anyway); the listen host's spectator PlayerState is local, so its entitled set never leaves the machine (`remote=0` rows in the player round prove the count logic, not the wire — the wire proof is the client's `n=0` lines, which the round also asserts).
- Dead player: `IsEntitled(Spectators, bOnlySpectator=false)` is false regardless of controller state; `Velox.GameMode.ItemTimerGating` pins it through take, death camera and respawn.
- Other PlayerStates: `COND_OwnerOnly` only; nothing owner-only is mirrored into the GameState.

### F10 — Baseline rule vs. the engine (info, passed)

Order verified: `PreNetReceive` is called once per bunch that carries properties (`DataReplication.cpp:1031–1035`, `:1140–1144`), `PostNetReceive` then `CallRepNotifies` (`:1602–1609`); so `bSuppressNetEvents` is set exactly across the first bunch's notifies and cleared before the next bunch's. Pickups are `bAlwaysRelevant` — no relevancy churn exists. Dormancy re-opens keep the replicator (no re-send, no spurious notifies) and `FlushNetDormancy` → `ForcePropertyCompare()` makes the push-model marks redundant-but-correct. `ResetLevel` keeps the actors (`bReceivedInitialState` persists), does not touch `TakeCount` (no false take), and `bAvailable` transitions produce the right cue (true = respawn cue, false = silent hide). Spawned pickups: `PostNetReceive` precedes `PostNetInit`/`BeginPlay`; `HandleReplicatedState` early-outs on `!HasActorBegunPlay()` and `BeginPlay` adopts `Seen*` — consistent. A prediction cannot coexist with the first bunch (the pawn does not exist before the join replication). C10's clock is gone with nothing lost: the "take 0.5 s before joining is not announced" case is the ADR's accepted trade.

### F11 — Bandwidth (info, passed)

`FRepLayout` dynamic-array delta: one changed element → its changed `float` (4 B) plus array/element handles; the PlayerState replicates at `ConfigNetUpdateFrequency=100` (`Config/DefaultGame.ini:46`) and every write calls `ForceNetUpdate()`, so a spectator sees a take within one server tick. The full set at entitlement gain is ≤ 23 × 5 B once. `ClearItemTimers` is a no-op when empty, so the per-event loop over non-entitled PlayerStates costs nothing on the wire. Well under the task's 100 B bound; the measured `max_err_s ≤ 0.017` is the value error, not latency, and is the right metric for a HUD clock.

`GameModes/VeloxPlayerController.h/.cpp`, `GameModes/VeloxSpectateMath.h` (F1.2 asked task 08 to cover `ViewAPlayer`), `Tests/VeloxDeathTests.cpp` (harness reuse), `Content/Data/MoveScripts/ItemGateRun.json`, the non-shipping `velox.items.LogTimers` in `VeloxPlayerState.cpp`. `docs/content-bootstrap.md` never named the deleted setting; unchanged is right. `Bots/` untouched and verified by reading. The forced-Live harness fix (`velox.bots.After 1 velox.match.Phase Live`) is a test-rig device, correct to keep out of the game code.

## Amendment text for ADR 0007 (append after F2 as **F3 — task 08 rulings**, once F1 is merged)

> **F3 — Item-timer gating (task 08, architect review `reviews/0007-08-review.md`, 2026-11-11).** (i) `AVeloxPickup::ItemIndex` (`uint8`, `COND_InitialOnly`, assigned by the server registry in `RegisterPickup`, **1-based; 0 = none**) is the key of `FVeloxItemTimerEntry`; clients map entries through `UVeloxItemRegistrySubsystem::FindPickupByIndex`. (ii) The baseline rule is as §5.5 states; engine order verified at `DataReplication.cpp:1031/1140` (`PreNetReceive`), `:1604` (`PostNetReceive`), `:1609` (`CallRepNotifies`). (iii) Every writer of `bOnlySpectator` calls `PushTimersTo` in the same function. (iv) `AVeloxPlayerController::ViewAPlayer` refuses non-spectator-only viewers and `AVeloxGameMode::CanSpectate` refuses spectator targets and self — this closes F1.2's note; the spectator follow-cam permission exists through the engine's `StartFire` path, only its UI is deferred. (v) Demos: `COND_OwnerOnly` timers are not recorded by the demo driver (`DataChannel.cpp:3812`); the M7 replays ADR decides on `COND_ReplayOrOwner`. (vi) Player names: uniqueness is 07's dedupe; log labels stay names; evaluators that need identity key on a separate `pid=` field.
