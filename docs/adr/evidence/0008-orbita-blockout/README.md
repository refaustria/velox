**Pad links (root cause of (c), of most of (e)).** At nav build `VeloxNav link_span` warns for VeloxNavLink_20/21/23/24/25 (P1, P2,
P4, P5, P6): their ends lie 2-4 nav tiles apart (TileSizeUU 1000; the pads span 22-35 m), so Detour never connects them. Only P3
(VeloxNavLink_22) is in the nav graph: all 8 JumpPad attempts in the FFA set are P3 (8/8). Scopulus is reachable only over P2, so the
FT and its two items fail, and Trabs is reachable only over Clivus Orientis (H25_3 untaken). No layout fix exists inside the concept:
a pad span > 2000 cm can never sit in adjacent 1000 cm tiles. Needs a per-map nav tile size (about 4000 on Orbita) or link splitting:
bot/nav task.

**Void deaths.** Self 182 / credited 96 over FFA x10 (per run 14-21), self 51 / credited 14 over BotDuel x3. By the victim's last
ground point (`voidwhy.py`): Hortus 27, Horreum 27, Armamentarium 27, Pons Fractus both halves 42 (the G1 JUMP gap: Jump aborted 137
vs ok 5, H11), hub edges 16, Clivus ramp 12, Trabs 11; last goal item 94 / fight 85. Samples: hopping at 900+ cm/s along the 400 cm
Semita deck past its edge, strafing off the Hortus jetty in a fight; airborne recovery fires and does not reach the deck. Bot edge
behaviour on narrow void decks, not a layout defect.

**FtMapReachability without WalkExempt.** Spawn S4 stands on Armamentarium, which joins the rest only over the G1 jump and pad P5;
no Walk path leaves it, so the walk check cannot pass on this map whatever is exempt. The row runs the Full-filter checks only.

**Bring-up changes to `orbita_layout.py`** (before the first set; navlint 8 clusters / 26 lowclear -> 0 / 0):
`FILL_NAV_KINDS = ("platform", "wall")` (nav inside covers, pylons, ramp fills, Corona/Specula blocks); K1 and its crate flush with
Horreum's south edge, HR_Parapet east half only; K2 100 cm south; HO_Rack2 into Hortus's north-east corner; clip caps on AR_Cover,
both racks, TRn_Back and the dish (their tops were walkable but eroded away). `mapgen.expected_counts` drops `clip: 0` (a map with
no clip spawned none; Orbita could not be generated). The one allowed layout iteration after the first set was **not** spent: no
failure has a layout cause.
