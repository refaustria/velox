# Velox CI scripts

Local CI until GitHub Actions is available (2026-11-01); afterwards the same scripts are the pre-merge check. See ADR 0001 sections 4 and 5.

## Running

Linux: `infra/ci/build.sh`   macOS: `infra/ci/build-mac.sh`

Configure via environment or `infra/.env` (copy `infra/env.example`; the real environment wins over the file):
`UE_ROOT` (required; on Mac `/Users/Shared/Epic Games/UE_5.8` is probed if unset, on Linux `/opt/UnrealEngine-5.8`), `VELOX_PROJECT` (default `<repo>/Velox.uproject`), `VELOX_OUT` (default `Saved/CI`), `VELOX_CONFIG` (default `Development`).

macOS notes: needs `brew install coreutils` (macOS has no `timeout`; `build-mac.sh` uses `gtimeout`, or runs the tests without a time limit and warns), Xcode, Launcher-installed UE 5.8; Server/Client targets are always SKIPPED. First-run walkthrough for the human: `docs/playtests/m1-movement-checklist.md`.

Flags: `--config X`, `--targets a,b`, `--no-tests`, `--tests-only`, `--clean`, `--net-soak` (Linux only: runs `nettest.sh` after build and tests, logs in `<log dir>/nettest/`), `--dry-run`, `-h`.
`--dry-run` prints every command without running it and needs no engine, only a directory with `Engine/Build/BatchFiles` (and optionally `Engine/Build/InstalledBuild.txt`).

Logs: `Saved/CI/<timestamp>/` (`build-<Target>.log`, `tests.log`, `automation/index.json`). Paths are printed on failure. Exit code is non-zero on any build or test failure.

## What SKIPPED means

`VeloxServer` and `VeloxClient` need a source-built engine. If `Engine/Build/InstalledBuild.txt` exists (Epic Launcher build, prebuilt Linux zip) the scripts print `SKIPPED (installed engine cannot build Server/Client targets)` and continue with exit code 0. On Mac, Server/Client are always skipped. This is not a pass for those targets; it means they are unverified.

## Tests

Runs `UnrealEditor-Cmd <project> -ExecCmds="Automation RunTests Velox; Quit" -TestExit="Automation Test Queue Empty" -ReportExportPath=<dir>/automation -nullrhi -unattended -nopause -nosplash -log`, then fails on any test in `index.json` whose state is not `Success`, on a missing report, or on `Test Completed. Result={Fail` in the log. The editor exit code is not trusted alone.

Add tests: put `IMPLEMENT_SIMPLE_AUTOMATION_TEST` tests named `Velox.<Area>.<Name>` in `Source/Velox/Tests/*Test.cpp` (wrapped in `#if WITH_DEV_AUTOMATION_TESTS`). The `Velox` filter picks them up automatically.

## Net soak (`infra/ci/nettest.sh`)

`infra/ci/nettest.sh [--scripts a,b] [--port N] [--timeout S] [--lag MS] [--repeat N [--keep-going]]` runs, per script (default `StrafeRun`, `PadRun`, `KnockbackRun`, `KnockbackGroundRun`, `LatchRun`, `CrouchRun`, `FireRun`, `FireRunControl`, `RocketJumpRun`), a dedicated server (`UnrealEditor-Cmd Velox.uproject <map> -server -nullrhi`, 60 Hz via `NetServerMaxTickRate`; `L_MovementTest`, or `L_CombatTest` for the three combat scripts) and one `-game -nullrhi` client (`t.MaxFPS 120`, `-VeloxScript=<name>`) with client-side packet simulation in both directions (`-PktLag=MS -PktLagVariance=20 -PktLoss=2 -PktIncomingLagMin=MS-20 -PktIncomingLagMax=MS+20 -PktIncomingLoss=2`; read from the command line by `UNetDriver::InitBase`). `MS` is per script (task 08b, D2): 100 (a round trip of about 200 ms) for the movement scripts and `RocketJumpRun`, **50 for `FireRun` and `FireRunControl`** (the ADR 0003 hitscan latency, 100 ms RTT: `MaxRewindSeconds` 0.25 cannot cover a 200 ms RTT plus the interpolation delay); `--lag MS` sets it for every script. It waits for the client's `VeloxNetSoak:` line (timeout 120 s), kills both processes, applies the per-script criteria of `docs/tasks/m1-movement/05-debug-tooling-and-net-soak.md` to both logs and prints one summary row per script (`C`/`max`/`mean` over non-echo corrections, `echoes=E` separately, ADR 0002 A24; every `VeloxReplay` line must start at the move after the correction, A25; `gaps=N` counts the server's `VeloxMoveGap` lines, i.e. server moves > 20 ms that merged lost RPCs or follow a slow client frame, A34(i); `repaired=N` counts the server's `VeloxMoveRepaired` lines, i.e. lost RPCs re-simulated in their own partition from the next RPC's OldMove, ADR 0002 A32; `resent=N` counts the client's `VeloxResend` lines, i.e. RPCs that carried an OldMove — the client runs with `log LogVeloxNet Verbose` and logs one `VeloxResend`/`VeloxSend` line per RPC (`rpcs=` in the detail column); since task M1-07 the line also carries `extra=<ts>` (`-1.000000` = none) when the second old move of the RPC was sent, and the detail column shows `extra=N`, the number of such RPCs — diagnostic only, no rule; `gaps + repaired == 0` over >= 500 RPCs fails as `loss simulation inactive`, `resent` below 90 % of the RPCs after the first ack fails, A34(ii); `strays_le_2_5=N` counts non-echo corrections <= 2.5 cm, the A31 class, A34(v)); exit code 1 if any script fails. `PadRun` (A28(iii)/A30(iii)/A34(iii)): per pad exactly one client `VeloxJumpPad: ... src=live applied=1` line and one server line with equal move time stamp `ts`; the first RPC after the entry move's own one (the launch move's RPC) must carry the entry move, as OldMove (`VeloxResend old=<entry ts> ... event=1`) or as its pending half (`pending=<entry ts>`); a `ts` mismatch is classified `lost entry move (burst loss, resend did not arrive)` when a `VeloxMoveGap` covers the entry `ts`, else — with position logs (`VELOX_NETTEST_EXEC="log LogNetPlayerMovement VeryVerbose"`) — `sub-threshold offset flipped the trigger (A31/B2)` when client and server positions at the entry `ts` differ by > 0.1 cm or `overlap ordering regression`, and without position logs both candidates are named; `src=replay applied=1` lines at most once per pad and replay, with the server's `ts`; `applied=0` (A19 teleport overlaps) ignored. `KnockbackRun`/`KnockbackGroundRun` grace (review 05/06 defect 9): the intended correction's response grace must equal `grace − (ts_resp − ts_start)` within 1e-3 for the server's last `VeloxKnockbackConsumed ts_start= ts_end= grace=` line (logged by the server move that consumed the knockback) with `ts_end ≤ ts_resp`. `KnockbackGroundRun` (A30): echoes with response grace > 0 keep `svel` within 1 % of the intended correction's, every burst correction is an echo, and after the grace expiry `t_exp = ts_c + grace_c` every burst response follows `svel_c * exp(-GroundFriction * (ts - t_exp))` within 3 % while that is > 1.2 x StopSpeed (GroundFriction/StopSpeed from the `event=info` line, defaults 6 / 250 when absent); a late stray whose acked move follows a `VeloxMoveGap` by <= 0.2 s is labelled `merged move during speed change (A31)` with the gap quoted (still a failure), A34(iv). Combat scripts (task 08, ADR 0003 §9, B17, B24, B25): **`FireRun`** (`Content/Data/MoveScripts/FireRun.json`; server ExecCmds `velox.combat.GiveAllWeapons, velox.combat.SpawnDummy <dummyLocation> invulnerable, velox.lagcomp.Debug 1, velox.combat.LagComp 1`) fires 10 rails at the strafing dummy (pauses spread the shots over its 1.5 s strafe period), the switch sequence RG → MG (40 shots) → RG with fire held through each switch, and one rocket at the floor under the strafe centre. Shots whose client `VeloxShotFired` line comes < 5 s after `VeloxShotSeqReset` (possession) are reported, not judged (B24). Asserts on the judged shots, matched to the server's `VeloxShot` line by `seq`: ≥ 10 rails, each with `aim_err_cm ≤ 30` and a server line; `hits` on the dummy and `hint=stamp` on ≥ n − 1; `rewind_ms ∈ [60, 250]`, `|rewind_ms − view_ms| ≤ 60` with mean ≤ 30, `snap=0` on every rail; ≥ 40 MG shots; `VeloxShotRejected` = 0 (server, all reasons) and `ClientActivateAbilityFailed` = 0 (client); a `VeloxProjectileExplode` of the rocket with `confirm_victims ≥ 1 confirm_sent=1`; client `VeloxHitConfirm` (logged by the scripted input component) ≥ server rail hits − 1 in the rail phase and ≥ all server-confirmed hits − (1 + 5 %) over the run; `VeloxLagCompRegister pawn=<dummy>` exactly once and no `VeloxLagCompRewind … mode=current` for the dummy; the global correction rules of `StrafeRun`. It writes `FireRun.railhits`. **`FireRunControl`** runs `FireRun.json` with `velox.combat.LagComp 0`; its one rule is rail hits strictly below the same round's `FireRun`. **`RocketJumpRun`** (no JSON) runs the client with `velox.move.LogCorrections 1, velox.combat.RocketJumpTest -90 quit` (server `velox.combat.GiveAllWeapons`): `result=PASS`; non-echo corrections in `[t_fire, t_fire + 0.6]` at most one ≤ 5 cm; exactly one server and one client `VeloxSelfSplash` with equal `seq` and `points`, `ts` within 1e-6, `hit=1` on both, `dist` within 1 cm; `VeloxProjectileShot` with `|client_ts − last_ts| ≤ 1/60 + RTT`; no `VeloxShotTimeClamp`; the rocket's `VeloxProjectileExplode … self=move_timed`; no `VeloxSelfSplash … forced by the deadline`. `--lag 125` / `--lag 250` repeat any of these at that one-way lag for every script (report-only: the FireRun gates are written for 50 ms one way, the movement gates for 100 ms). `--repeat N` runs the list N times (logs in `round-<k>/`), stopping at the first failing round unless `--keep-going`. Logs: `Saved/CI/<timestamp>-<pid>/nettest/<script>-{server,client}.log` and `<script>.result`. UDP 7777 must be free (`ss -ulnp`). `VELOX_NETTEST_EXEC="p.NetShowCorrections 1"` adds console commands to both processes (debugging). Fixed time step is deliberately not used: it runs frames as fast as possible and the wall-clock packet simulation would then add seconds of game time per 100 ms.

## Caveats

Not executed against a real engine: Unreal Engine is not installed on the dev VM. Only `--dry-run` and error paths have been verified. The `index.json` field names (`tests[].fullTestPath`, `state`) follow the UE automation report format and must be confirmed on first real run.
shellcheck: no suppressions.
